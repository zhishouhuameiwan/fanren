### 10.2 判据的要点

- **契约 E1**（以契约为准，这里只是摘要）：夹具 `tests/fixtures/ch11-end-first.sav`（`realm 31 / cap 31`，判据不依赖章节进度；修为由用例直接写）。四态：上限 31 → `StoryCap`；探针脚本 `realm.cap` 返回 true 后，修为 4999 → `NotEnough`、5000 → `None` 且把握 85；同一颗种子冲成 → `realm 32`、`maxHp == rules::realmMaxHp(32)`、`maxMp == rules::realmMaxMp(32)`、再按 → `StoryCap`；冲败 → 修为倒扣两成（走火四成）、`realm` 不变。静室 150 坐 360 日与规则层 `meditate` 同种子逐点相等。**负向**：去掉 `realm.cap` 那一步 → 面板永远 `StoryCap`；设施去掉 `effectiveness` → 进账回到 100 那条，用例红。
- **契约 E2**（以契约为准）：同一夹具，用例先确保 `field_tianxing_39` 至少一槽有作物（真档若空，用例自己种一株、记下年份）；从 `ch13_tianxing` 的设施进 → 槽位、作物、年份与存档逐字段相同；采收 → 背包多一株、`herbAge` 不丢；**负向**：把设施 `ref_id` 改成新 id → 得到空田（证明上一条读的是旧田而非新建）。真数据跑 `validate.py`：两张图同一 `ref_id` 零报错；若报，C8 落地后同一条转绿、同图两处同 `ref_id` 的负例仍红。

- **T2**：`kScriptTransfers` 7 条逐条跑脚本到那一行，`mapId` 等于落点图；五元两条的触发器 `type trigger / mode enter / once false / guard_flag == "ch13.lifu" / set_flag` 空、`qiyuan_hang.lua` 与 `hui_wuzhong.lua` 各 0 处 `flag.set`；`kOffChainFlags` 7 面都不在 `data/objectives/ch13.json` 的 `done_flag` 序列里、却都在 `data/flags.json` 里。
- **B1**：两侧意图起点——① 五行环削势 3 能把儒生打进破势、大汉的白玉大印蓄势要么被破势打断要么防御硬接得住、儒生的怪鸟只压法力；② 第 0 波剑与土省法、第 1 波巨虾 `actions 2` 下蓄势能被五行环或剑打断、**只有剑与木要得了它的命**。最低合法起点——两场都打得过。数值改动落在内容路的 role / battle 文件里，测量记录写进编成的 `note`，由协调者并入第 18 节。
