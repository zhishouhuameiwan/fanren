## 0. 参考对象与总取向

参考《八方旅人》（Octopath Traveler，中文版《歧路旅人》）的三样东西：

| 维度 | 八方旅人的做法 | 本作怎么落 |
| --- | --- | --- |
| 画面 | HD-2D：像素人物 + 立体场景 + 移轴景深、体积光、辉光、粒子、暗角 | 16px 像素美术 + 预烘焙地图 + 渲染目标后处理（景深/光照/辉光/暗角/调色）+ 粒子 |
| 玩法 | 「Break & Boost」：敌人有护盾与弱点，打弱点削盾，盾破则晕一回合且受伤翻倍；每回合攒 1 BP，出手可花 1–3 BP 强化 | 「**破势与蓄劲**」：横版回合制，敌人有「架势」与「破绽」，架势归零即「破势」；每回合积一点「劲」，出手可「蓄劲」 |
| 玩法 | 路径行动（打听/偷盗/决斗/引导）：对 NPC 的特殊交互 | 「**路径行动**」：打探（情报）、求购（物件）、切磋（决斗） |
| 玩法 | 野外随机遭遇、区域危险度 | 第 3–5 章野外图接上既有的遭遇表规则（规则层早已写好、缺加载器与入口） |
| 风格 | 章节标题卡、地名横幅、金边深色 UI、标题画面、战斗胜利结算 | 同，配色取「墨色 + 金线 + 宣纸白」 |
| 风格 | 管弦乐 | 程序合成的五声音阶弹拨乐（Karplus-Strong 拟古筝/琵琶）+ 程序合成音效 |

**不改的**：剧情节点、文案正文、原著约束（名词首见章号、不转写）、Lua 协程架构、数据驱动、三道门禁、

## 1. 共享决策（所有路都必须遵守）

### 1.1 像素尺度

| 场合 | 美术分辨率 | 屏幕放大 | 屏幕尺寸 |
| --- | --- | --- | --- |
| 地图瓦片 | 16×16 / 格 | ×3 | 48×48 / 格 |
| 行走人物 | 16×24（一格宽、一格半高） | ×3 | 48×72 |
| 战斗背景 | 320×180 | ×4 | 1280×720 |
| 战斗人物（我方） | 16×24 同一张行走图的侧身帧 | ×4 | 64×96 |
| 战斗敌人 | 16×24（人形，与行走图同一套生成器）/ 24–48 见方（兽、怪、光球） | ×4 | 64–192 |

- **地图逻辑坐标不变**：格子仍是 `kTileSize = 32` 的逻辑格，地图、碰撞、对象、测试全都不动。
  「一格在屏幕上画多大」是渲染层的事，新常量 `kWorldTilePx = 48`（屏幕像素/格）只在渲染层出现。
- 像素美术一律 `SDL_SCALEMODE_PIXELART`（SDL 3.4 起有，平滑亚像素移动不糊边）；后处理用的模糊目标用 `LINEAR`。
- 文字**不**像素化：名牌、对白、菜单一律按逻辑分辨率 1280×720 原生绘制——「像素世界 + 高清字」本身就是 HD-2D 的一部分。

### 1.2 资产目录

```
tools/artgen/                 生成器（Python + PIL，确定性，同输入同输出）
data/visual/looks.json        角色外观（role_id → 发型/肤色/衣色/体型/配件），人工维护
data/visual/maps.json         地图视觉预设（map_id → 主题/时辰/粒子/环境光/景深/战斗背景），人工维护
data/visual/battles.json      战斗背景覆写（battle_id → backdrop），可选
assets/art/maps/<map_id>/below.png   烘焙：地表+叠加+建筑（人物之下）
assets/art/maps/<map_id>/above.png   烘焙：树冠/屋檐（人物之上）
assets/art/maps/<map_id>/meta.json   烘焙附带：光源、水面格、粒子发射区、主题、时辰
assets/art/sprites/chars/<look>.png  人物行走+战斗帧
assets/art/sprites/enemies/<id>.png  非人形敌人
assets/art/sprites/index.json        role_id → 图、帧尺寸、帧表
assets/art/battle/<backdrop>.png     战斗背景
assets/art/fx/*.png                  光斑、柔圆、叶、花瓣、火星、碎片、刀光……
assets/bgm/*.wav  assets/sfx/*.wav   程序合成音频
```

- 运行时**只读 `assets/art/**` 的生成物**；`data/visual/*` 是生成器的输入。
- 生成物进仓库（与 `maps/*.tmj` 同理：它们是生成器的产物，漂移由门禁查）。
- 新门禁 `python tools/artgen/artgen.py --check` → `ARTGEN_IN_SYNC`：重生成到临时目录，逐像素比对（不比字节，避开 zlib 差异）。
  必须快（目标 < 30 秒），否则会拖慢每一次构建。
- **缺图不崩**：任何一张图缺失，渲染退回旧的图元画法（`MapArt::drawTile` / `drawFigure` 保留），并打一行 WARNING。
  这是为了让「美术还在路上」时游戏照样能跑、测试照样能过，不是防御性兜底——旧画法本来就是完整实现。

### 1.3 地图烘焙（为什么烘焙而不是运行时拼瓦片）

地图的瓦片语义只有 9 种（`MapArt.h` 的 `TileRole`），墙就是墙，分不出是屋、城墙还是崖壁。
要画出屋顶、檐口、门脸、树冠、崖面，就得看邻格（自动接边）、看连通块（整栋屋子）。
这套推断放在 Python 烘焙器里做一次，运行时只贴两张大图：

- **一份实现**：接边规则只活在 `tools/artgen/` 里，C++ 不再各写一套。
- **能画多格结构**：一整栋屋子的屋脊、一棵大树的树冠、崖面的岩层，不受「一格一图」的限制。
- **运行时极简**：`below.png` → 人物（按 y 排序）→ `above.png`（主角附近半透明）→ 光照/粒子/后处理。
- 地图是生成器产出的（`tools/mapgen/`，24 张全是），烘焙器读 `.tmj`，与 `MAPGEN_IN_SYNC` 同一条链。

`MapArt.h` 的 `tileRole` 语义表**仍是契约**（`MapArtTests` 照旧钉着它），烘焙器按同一张表读 gid。

### 1.4 引擎新接口（`src/engine/Engine.h`，引擎路负责）

SDL 类型仍不出头文件。新增（签名以实现为准，这里是能力清单）：

- 渲染目标：建 / 切换 / 清屏；纹理尺寸查询；缩放模式（像素 / 线性）。
- 混合模式：`None / Alpha / Add / Mod / Mul`；纹理的颜色与透明度调制。
- 浮点矩形绘制、水平/垂直翻转、旋转；带顶点色的几何（渐变带、扇形、光束）。
- 程序纹理：从 RGBA 像素数组建纹理（径向渐变、暗角等在运行时生成）。
- 裁剪矩形；文字描边/投影（`drawText` 的扩展版）。
- 帧时钟（累计秒数），给粒子与动画用。
- **无头模式下全部是合法空操作**，与既有契约一致。

后处理管线（`src/engine/PostFx.*`，引擎路负责）：

```
场景 → sceneRT（1280×720）
  ├─ 光照：lightRT 填环境色，点光源径向图 Add 叠上去，再以 Mod 乘回 sceneRT
  ├─ 辉光：emissiveRT（只画发光体）→ 降采样三级 → Add 回 sceneRT
  ├─ 景深：sceneRT → 降采样模糊图；上下两条渐变带（顶点色 alpha）盖回去 = 移轴
  └─ 暗角 + 调色（Mod/Add 各一层）
→ 后缓冲 → UI（清晰，不进后处理）
```

参数全部来自地图视觉预设（`meta.json`），战斗场景有自己的一套。

## 2. 战斗：破势与蓄劲

（本节由战斗路细化；协调者先给骨架，数值与测试口径以战斗路交付的 `docs/octopath-battle.md` 为准。）

### 2.1 形态

- **横版**：敌人在左、我方在右（斜排），不再有格子、移动、射程、相邻。
- **行动序**：每回合按身法排序（带种子随机的小幅扰动），界面顶端同时显示**本回合与下回合**的行动序。
- 每人每回合出手一次（首领可多次，见 2.5）。

### 2.2 破绽与架势（Break）

- 每个敌人有 **架势**（护盾点，杂兵 2–4，头目 5–8，首领 10–20）和若干 **破绽**（攻击类别）。
- 攻击类别（本作取十种）：兵刃 **剑 / 刀 / 拳 / 暗器 / 毒**，五行 **金 / 木 / 水 / 火 / 土**。
- 破绽初始显示为「？」，被打中一次即揭开（也可由路径行动「打探」提前揭开）。
- 每一「击」若命中破绽，架势 −1；架势归零即 **破势**：
  - 本回合若尚未出手则失去本回合，并失去下一回合；
  - 破势期间所受伤害 **×2**；
  - 破势结束（它的下一次该出手时）架势回满。

### 2.3 劲与蓄劲（Boost）

- 我方每人开场 1 点劲；每回合开始 +1，**上限 5**；本回合蓄过劲的人下回合开始不加。
- 出手时可蓄劲 0–3 点：普攻 = 连击 1+N 次（每击单独判破绽）；法术 = 威力 ×(1+N)（或 1+N 发）；物品不可蓄。
- 按键：命令菜单里左右键增减，角色身上的金色气焰随档位变大。

### 2.4 其余规则

- 防御：受伤减半直到下次出手，且下回合排在最前。
- 伤害公式**沿用** `Damage.cpp`（平砍 攻×2−防、法术 威力×2−防×0.5、境界压制、五行相克），在其外乘破势 ×2、防御 ×0.5。
  沿用是有意的：前四章设计文档里所有「几下打死一个」的推算仍然成立，重调的只是节奏。
- 毒、逃跑、物品、多波次、战后奖励、识海吞噬战：概念全部保留，搬到横版上。

### 2.5 首领

- 每回合行动数 `actions`（缺省 1）；
- **蓄势**：首领宣告下一手是重招（头顶出现暗红气焰与一句预告），在它出手前把它打到破势即可打断——八方旅人最有名的那一口气。

## 3. 画面：HD-2D

- 地图：烘焙图 + 按 y 排序的人物 + 脚下柔影 + 树冠/屋檐在主角附近半透明。
- 移动：格子逻辑不变（`tryStep` 仍是瞬移一格），**画面上**人物在两格之间插值滑动 0.12 秒并播走路帧；镜头平滑跟随。
- 光照：每张图一个时辰预设（昼 / 黄昏 / 夜 / 室内），夜里灯笼、窗、丹炉、火盆自带光源；主角夜里身上一团微光。
- 粒子：按主题选（尘埃光点、萤火、落叶、花瓣、雨、火星、薄雾）。
- 景深：上下两条移轴带，强度随预设。
- 转场：传送点 `transition:"fade"`（44 个传送点全是）真正淡出淡入；脚本 `fade.out/in`、`wait` 落地；开战「碎屏」转场。

## 4. 风格

- 标题画面（无 `--load` / `--map` 时）：生成的远山云海背景 + 「凡人修仙传」+ 新的旅程 / 读取存档 / 离开。
- 章节标题卡：每章开篇「第一章　山村·七玄门」，章末「第一章　终」。Lua 新接口 `chapter.begin(n)` / `chapter.finish(n)`。
- 地名横幅：进图时左上角淡入地名（野外图附「危险」星级），数秒后淡出。
- 对话框：底部墨金框 + 左上名签；正文逐字；右下闪烁的「▼」。
- 主菜单（Tab / Esc）：状态 · 物品 · 法术 · 记事 · 存盘 · 返回。
- 战斗胜利结算：「胜」字 + 修为 / 碎银 / 物品逐行飞入（技术债 G-15「奖励到手没有一句话」在这里一并还掉）。
- BGM 13 首（地图属性里已写好的 id）+ 战斗 / 首领 / 胜利 / 标题 4 首；音效：光标、确定、取消、打击、破绽、破势、蓄劲、升阶、开门。

## 5. 玩法新增

### 5.1 路径行动

- **打探**（第 1 章起）：韩立向 NPC 打听。按 NPC 条目的「阅历门槛」（以长春功层数/境界计）判定能否问出来；
  问出来的是一段情报，可能附带：置旗标、揭开某场战斗的破绽、让一件隐藏物件出现、给商店折扣旗标。
- **求购**（第 2 章起）：向特定 NPC 用碎银买一件独有物件（每条只能买一次）。
- **切磋**（第 3 章起，战斗开放之后）：与特定 NPC 过招，赢了有奖励，输了不 game over。
- 数据：`data/pathactions/chNN.json`（按章分片），文案进 `data/text/chNN_path.json`（带 chNN 前缀，禁词闸门自动覆盖）。
- 入口：面对 NPC 按 `E`；NPC 头顶有可用路径行动时浮一个小图标。

### 5.2 野外遭遇

- 地图上的 `encounter` 对象（`map_spec` 4.5 早已定义）+ `data/encounters/`（已有 3 张表）+ `rules::Encounter`（已有）
  → 补加载器与 `WorldScene` 入口。**默认由启动器（`main.cpp`）打开**，`Application` 缺省关闭，测试不受影响。
- 只放在第 3–5 章的野外图（谷外、落日峰山道、嘉元城郊、渡口野地、独霸山庄外），每日上限沿用规则层。
- 遭遇战奖励只给少量碎银与药材，修为照走境界上限（不会把章节曲线打穿）。
