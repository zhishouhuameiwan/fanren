已修（不再是债）：**G-10 境界只给气血与法力，不给攻防。**
`src/core/rules/Realm.h/.cpp` 新增 `realmAttack` / `realmDefence`，与 `realmMaxHp` /
`realmMaxMp` 并排同体例；`BattleScene.cpp` 原先写死的两处 6/3（`buildFromSetup`
与 `buildProbeEncounter`）从此取自境界。契约写在 `docs/interfaces-p3-ch04.md` 第 6 节。

**曲线就是这一行里解好的那两条，锚定也照这一行写的做了**：攻 ≈ 3 + 1.8×层、
防 ≈ 4 + 层，整条锚在「炼气三层 = 6/3」上，落成
`攻 = max(6, round(0.6 + 1.8×层数))`、`防 = max(3, 层数)`。
于是**第 1-3 章一个数没动**（凡人与炼气一至三层全是 6/3），本行原先担心的两件事
——抬攻打坏教学战二、抬防打坏教学战一——都没有发生：实测 783 → 804 条测试全绿，
第 3 章那两场教学战的断言一条没动。炼气七层现在是攻 13 / 防 7，
十三层攻 24 / 防 13。

三件事一并记下：

· **筑基以上是暂定值**（筑基初 32/20 … 结丹后 102/82），Realm.h 里写明「到那一章
  再标定」。那几档一场仗都还没编，没有任何一场战斗能验证它们；单测把它们钉住，
  为的是标定时必须经过那条测试，而不是被人悄悄改掉。
· **识海那一场不另开攻防口径**，是判断不是遗漏：吞噬模式下 `applyAttack` 走
  `devour_ ? devourBite(...) : physicalDamage(...)`，攻防一概不参与。体积仍然特判。
· **单测逐层钉死十三层**，不是钉一两个点。锚定之后前四档全是 6/3，一个「恒返回
  6/3」的实现能穿过前四个点——那正是这条债原本的样子。实测变异（把斜率改成
  `round(1.8×层)`，锚点仍是 6）确实只有逐层那条测试抓得住。

**注意 G-10 只解了 CRITICAL-1 的一半。** 另一半是「脚本改不动境界」，
与本条同一批做掉：新命令 `realm_advance` 与只读查询 `__host.realm_value`，
契约同在第 6 节。**但 `scripts/common/api.lua` 的糖衣还没加**（那批白名单不含
`scripts/**`），在它落地之前这条命令在剧情脚本里还用不上。

（「超出 蚀心散 的使用距离：相距 5 格，只及 3 格」）。

写的正是「砍不动就下毒」。无限射程会让下毒变成无脑最优解，那一课就教不成。

加载器：缺字段按 1 收（**老数据一行不改照读**），负数与非整数当场报错，不夹到 0
——写 -1 的人本意多半是「不限」，夹成 0 会让这件东西只能用在自己身上，而症状是
「这药怎么递不出去」。三条都配了负向用例，改坏加载器与改坏判定都验过转红。

`src/io/BattleLoader.cpp:185`、`src/io/RecipeLoader.cpp:201`、`src/io/ShopLoader.cpp:116` 都是

### G-27：第 4 章攻防战只钉了上界，没钉下界（终审 M-2）

**是什么。** `Ch04SliceTests.cpp:1665` 一带钉的是「揣够设计的 8 瓶必赢」（上界）。终审把攻防战四类敌人的攻击全部减半，
只有章末存档对不上的那两条红，平衡扫描照样全绿——也就是说**「这一仗太容易了」没有任何判据会报**。
三选一的风险 / 回报排序（第 4 章二次复验 R-1、技术债 G-21）因此也没有下界守着。

**为什么这次不修。** 下界要定一个「最少要几瓶」的底线（例如「0 瓶必输」或「最费那张不少于 N 瓶」），那是设计取舍，
而 R-1 当时就是「交设计方定夺、暂不调」。

**什么时候修、怎么修。** 与 G-21 / G-22 一起：先由设计定下界口径，再在「最少要几瓶」扫描里加一行断言
（例：围歼在门槛 40/50/60/70 下最少瓶数都 ≥ 4），并做一次「攻击减半必红」的负向验证。
