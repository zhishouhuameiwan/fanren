# 第 7 章试玩返修·路 U：得物卡片、收集进度、集齐奖励（2026-11-20）

> 同一天另外两路并行：路 F（明雷巡逻与追击）、路 L（妖兽专属掉落、宝箱内容、丹方、伙伴喜好）。本路**不改宝箱里装什么**。

---

## 1. 用户原话与选定

用户 2026-11-20 试玩第 7 章，原话：

> 找东西没啥回报感

用户选定的两件事：

1. **得物弹窗**：拿到东西时弹一个带图标、按品阶上色、有音效的小卡片，代替现在的一行旁白。
2. **每张图的收集进度**：地名下显示「宝箱 2/3 · 采集 1/2」，一张图找齐给一份奖励。

改之前：开箱 / 采集压一个 `DialogueScene` 说一句「打开箱子，得了{items}。」/「采得{items}。」，要按确认才收得掉；
帧末响 `item_get`。没有图标、没有品阶色、没有「找到几个 / 共几个」。

## 2. 得物卡片（`game/ItemToasts.*`）

**不挡路**：卡片不是场景，不进场景栈，不收输入——人照走、对白照演。

| 项 | 做法 |
| --- | --- |
| 谁弹 | 开箱、采集（`WorldScene::openChest / gatherAt`）、脚本 `give()`（`Application::dispatch` 的 `GiveItem`）、路径行动给物（`applyPathEffect` 的 `GiveItem`）、集齐奖励。都经 `Application::announceItem(itemId, count)`：推一张卡片 + `noteItemsGiven()`（帧末响一声 `item_get`，一帧给几样只响一声，与从前同口径） |
| 一件一张 | 一次给几样，后一张晚 0.18 秒出场；淡入 0.2 秒（从右边滑进 24 像素）、停 3.2 秒、淡出 0.5 秒，**自己没了，不用按键** |
| 叠放 | 屏幕右侧、存盘提示之下（y = 132 起），自上往下排，每张 380×60；同时至多 6 张，再多挤掉最早那张 |
| 按确认提前收 | 世界层上按确认，**而面前没有别的能按的东西**（`interactHint` 为空——多半正对着刚开空的箱子）：这一下收起卡片（0.18 秒淡完），不再弹「箱子是空的」。面前有能按的（另一个箱子、一个人）照常交互，卡片自己淡出 |
| 什么时候走时钟 | 世界层露着时（从栈顶往下第一层不透明的是世界层）。给完东西紧接着开战、开菜单，卡片停着，回到地图上接着放完 |
| 画在哪一层 | `Application::drawScenes` 紧跟着世界层（与脚本黑幕之上）画：对话框压在它上面，一边读对白一边看得见刚拿到了什么；卡片盖住主角时淡成 0.35（与目标框同一个数） |
| 对话记录 | **照旧**记一行「打开箱子，得了丹砂×2、符纸。」/「采得黄精。」（回看面板与测试都认它）。空箱子、采过了、背包满了这几句仍是对话框 |
| 读档 / 新开局 / 返回首页 | 清掉卡片：上一局拿到的不在这一局弹出来 |

卡片上写什么（`makeItemToast`）：

* **名字**按品阶上色（`ui::Theme::gradeColors`，色值在 `ui::palette` 的 `kGrade*`）：

  | 品阶 | 档 | 颜色 |
  | --- | --- | --- |
  | 0–1 | 0 凡品 | 正文色 `#F1EAD8` |
  | 2–3 | 1 | 青 `#8CE8AC` |
  | 4–5 | 2 | 蓝 `#82BAFF` |
  | 6–7 | 3 | 紫 `#CC96FF` |
  | 8 以上 | 4 | 橙金 `#FFBA5C` |

  左缘一道同色竖条、图标框也是这一色。
* **×数量**：一律写（×1 也写）。
* **说明**：物品说明文案（`descKey`）的第一句——到第一个「。！？」为止、不含标点；超过 21 个字截成 20 个字接「…」。
* **钱**（`material_lingshi`）：名字跟着阶段走（`Wording::currencyName`，第 1–5 章叫「碎银」），**不写说明**——灵石那句说明里有「灵气」，凡人篇说不得。
* **图标**：没有逐物品的图标，按种类取 `art/ui/icons.png` 里现成的一格（`itemIcon`）：

  | 种类 | 图标 |
  | --- | --- |
  | 丹药 | 药瓶（带毒的是毒那一格） |
  | 灵草 | 叶（木） |
  | 材料 | 土丘（土） |
  | 符箓、护具 | 架势圈 |
  | 法器 | 兵器按它给的攻击类别（剑、刀……），不是兵器的是金铃 |
  | 饰物（阵盘之类） | 金珠 |
  | 功法 | 修为玉璧 |
  | 剧情物、查不到的 | 宝箱 |
  | 钱 | 碎银 |

## 3. 每张图的收集进度（`game/Exploration.*`、`WorldFrame::exploreLine`）

* 显示：**目标框底下**一小条「宝箱 2/3 · 采集 1/2」（没有目标时顶到目标框的位置）。不放在地名横幅里：横幅几秒就淡了，进度要随时看得到。比目标框轻一档（墨底、细框、行首小菱形）；盖住主角时淡成 0.35（`WorldView::drawHud` 的 `covers`）。找齐了末尾接「 · 已寻遍」，整条换金字。图上没有采集点就不写那一截，没有宝箱同理；两样都没有就不显示。
* 只数此刻**在场**的：`require_flag` 没置的宝箱、采集点不画、不占格，也不进分母（`worldobj::present`）。
* 宝箱「开了」看 `openedChests`；采集点「采过」看 `gatheredDay` 里有没有它——**采过一次就一直算**，冷却好了又能采不把它退回去。`gatheredDay` 本来就进存档，所以「采过」读档后照样在，**不加存档字段、不升版本**，`tests/fixtures` 的交接档原样读。
* **历练里不显示、也不发集齐奖励**，理由三条：
  1. 带 `chance` 的宝箱没抽中时直接记成「已开」（看上去是被人先开过的），一进去就是「宝箱 2/3」，数是假的；
  2. 那一趟的账出来就扔，每趟都能再集齐一次，奖励就成了刷的东西；
  3. 历练的宝箱本来就带灵石（`lilian_jindi_*` 的 loot），回报在那里。

  单算「这一趟」也做得到，但上面第 1 条让那个数没法读，所以选不显示。

## 4. 集齐奖励（`data/exploration/ch07.json`、`io/ExplorationLoader.*`、`explore::settle`）

一张图在场的宝箱全开、采集点都采过 → 置那张图的旗标、发灵石与一样材料（各弹一张卡片）、此刻**上场**的伙伴各加默契，再旁白一句（进对话记录，压一个对话框——一张图只有这一次）：

> 禁地外围能找的都找到了，又在角落里拾得灵石×10、寒烟草。（她在场时再接）白衣少女与你更有默契了。

* **每张图只给一次**：旗标登记在 `data/flags.json`（`ch07.xunbian_*`），进存档，读档后不重复；后来又冒出一个箱子（某个 `require_flag` 置了）让这张图「不齐」了，再开齐也不再发。
* 什么时候判：开箱、采集那一下之后（`announceHaul` → `explore::settle`）。**不在进图时判**：改动之前就已经把一张图搜空了的老存档，不会补发这一份（交接档里没有这种图，第 7 章的最小路线只采了沼泽深处一处矿脉）。
* 默契：`rules::addBond`，不受「并肩每天至多 +6」管（那是打仗的账）。只给上场的（跟着走的那几位，`worldobj::fieldedCompanionRoles`），在队不上场的不加。
* 历练里不发（第 3 节）。没配的图只显示进度，不发奖。

先只给第 7 章禁地那六张图配：

| 图 | 宝箱 / 采集点 | 灵石 | 材料 | 默契（上场伙伴各） | 旗标 |
| --- | --- | --- | --- | --- | --- |
| 禁地外围 `ch07_jindi_waiwei` | 2 / 1 | 10 | 寒烟草 1 | +1 | `ch07.xunbian_waiwei` |
| 中心区外 `ch07_jindi_zhongxin` | 2 / 1 | 10 | 火龙草 1 | +1 | `ch07.xunbian_zhongxin` |
| 环形山 `ch07_huanxingshan` | 3 / 1 | 15 | 火龙草 1 | +1 | `ch07.xunbian_huanxingshan` |
| 地下沼泽 `ch07_dixia_zhaoze` | 1 / 0 | 8 | 寒烟草 1 | +1 | `ch07.xunbian_zhaoze` |
| 沼泽深处 `ch07_zhaoze_shenchu` | 1 / 2 | 12 | 火灵石 1 | +1 | `ch07.xunbian_shenchu` |
| 地底石窟 `ch07_dixia_shiku` | 2 / 0 | 12 | 火灵石 1 | +1 | `ch07.xunbian_shiku` |

量的口径（`docs/ch07-balance.md`）：

* 章末灵石约 450（第 7 节）；六张全找齐合计 **67 块**，一成半。材料都是禁地里本就采得到的（寒烟草、火龙草 8 块一株，火灵石 12），合计约 60 块的东西。
* **一颗药也不给**：② ③「要吃药」是平衡路钉的判据，全收集路线不能因此变松。
* 默契：她只在后三张图上跟着（墨蛟那一仗入队、问名离队），全收集路线因此 +3（实测 53 → 56）。最小路线不碰任何一张图的「找齐」，37 不变；三档（45）早已过、四档（70）还远，「四档以上留给历练」不受影响。
* 写成数据：`{"map", "done_flag", "spirit_stones", "items": [{"itemId", "count"}], "bond"}`，形状由 `io::loadExplorationRewards` 查（表外字段、取值范围、一张图或一面旗配两遍都拒），物品 id 由 `Application::init` 对一遍；门禁 `tools/validate.py` 只改了一处——`collect_data` 跳过 `data/exploration/`（它不是一份一条的数据），`done_flag`、`itemId` 照常由 `check_data_references` 查。**按用户要求没有跑门禁。**

## 5. 测试

新增 `tests/ExplorationTests.cpp`（期望值照本文写死）：

* `ItemToastRules`：品阶五档、说明第一句与截断、按种类挑图标、钱按阶段叫名且不写说明、错开出场 / 停 / 自己淡出、按确认快收且排队的不再出场、至多 6 张、叠放位置。

* `ExplorationData`：真树上的六张图、旗标已登记、数额照第 4 节的表、合计 67、每张图上真有可数的东西。
* `ExplorationWorld`（探针图，真 `Application` + `WorldScene`）：开箱弹卡片（名字、×数量、颜色档、图标、说明）且栈顶仍是世界层、对话记录照旧有那一行；采集同样；卡片亮着照样走、五秒内自己没了；按确认收卡片、面前有箱子时照常开箱；脚本 `give()` 弹卡片而对白照演；进度只数在场的、开一个 +1、读档后保持、冷却好了不退；找齐只奖一次、只给上场的伙伴、读档后不重复；历练里不显示不发奖；没有宝箱采集点的图不显示；截图口 `walk` 的 `Z` / `.`；读档清掉卡片。

## 6. 截图自查

截图口的 `walk:<串>` 多认两个字：`Z`（面朝前方按确认）、`.`（空转 0.25 秒，等卡片淡入）。

```
build-u\fanren.exe --assets . --load saves\ch07-jindi.sav --screenshot <png>
build-u\fanren.exe --assets . --load saves\ch07-jindi.sav --scene walk:UUUUUUUUUUUUUUUUUUUUUUUURRRRRRRUZ.. --screenshot <png>
```

第一张是禁地外围起点：目标框底下「宝箱 0/2 · 采集 0/1」。第二张走到崖下那只箱子跟前开箱（两瓶金疮药）：右侧一张卡片、进度变成「宝箱 1/2」。

## 7. 没做的、拿不准的

* 卡片没有逐物品的图标，按种类挑现成的九格（第 2 节那张表）；符箓、护具借的是「架势」那一格。要逐物品的图，得美术路出一张物品图集。
* 战斗的战果卡、炼丹出炉、商店买到的东西不弹卡片：那几处各有自己的面板说「得了什么」。
* 集齐奖励不在进图时补判（第 4 节）：老存档里早已搜空的图拿不到这一份。
* 进度那一行不随数字变化闪一下；找齐时只是换金字、接「已寻遍」，外加那一句旁白。
