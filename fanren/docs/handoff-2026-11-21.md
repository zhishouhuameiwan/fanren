## 1. 新电脑上怎么开工

### 1.1 取代码、搭环境

```powershell
git clone https://github.com/zhishouhuameiwan/fanren.git
cd fanren\fanren
pip install numpy pillow scipy
.\build_quick.bat main
```

- 需要 Visual Studio（带 C++ 工具集，旧电脑是 VS 2026 Build Tools / MSVC 14.52）、CMake 3.25 以上、Ninja、Python 3。
- **日常只用 `build_quick.bat`，不要用 `build.bat`。** `build.bat` 先跑四道内容门禁，单是自检就可能跑一个多小时，而用户定了不跑门禁（第 2 节）。`build_quick.bat <槽名>` 只做：下载第三方库（`bootstrap.py`，按 SHA256 校验，放进不入库的 `vendor/`）→ CMake + Ninja 构建到 `build-<槽名>\` → `ctest -j 4`。加第二个参数 `notest` 只构建不跑测试。
- 判断成败看输出里的标记行：`BUILD_DONE`、`CTEST_EXIT=0`。全量测试 2543 条（其中 3 条是设了环境变量才跑的辅助，平时记为 Skipped），四核约 7–11 分钟。
- vswhere 找不到 Visual Studio 时，先 `set "VSPATH=<VS 安装根目录>"` 再跑。
- 一台电脑上装了两套 Visual Studio 时要小心：脚本挑最新的那套，可构建目录记着它第一次配置时用的编译器，两套混用会每个文件都报 `error STL1001: Unexpected compiler version`（旧电脑上就踩到了）。要么把 `VSPATH` 指到那个目录当初用的那一套，要么删掉构建目录重新配置。
- macOS 上日常用 **`./build_quick.sh <槽名>`**（`build_quick.bat` 的对应物，不跑门禁；`notest`、`--log` 与标记行同上；`cmake` / `ninja` 是 `pip install --user` 装的、不在 PATH 上时，脚本自动用 `~/Library/Python/3.*/bin` 里的那一份）。`build.sh` 先跑门禁，别日常用。2026-11-21 在新电脑（Intel x86_64、macOS 15.8、12 核、Apple clang 17）上实测 main `369932b`：经指向主检出 `vendor/` 的符号链接，`./build_quick.sh --log v` 从空构建目录到跑完约 6.5 分钟（构建约 4 分钟，ctest `-j 12` 157 秒）；**2540 条、0 失败**，其中 3 条辅助记为 Skipped，`CTEST_EXIT=0`。比 Windows 少的 3 条是只在 MSVC 下编译的 `PortableDeterminismOnMsvc.*`，不是丢了。同道录两份试玩档在 Mac 上重生成与入库的逐字节相同。过程与截图清单见 `docs/macos-verify-2026-11-21.md`。

## 7. 子会话怎么带（旧电脑上摸出来的做法）

- 一路一个子会话、一个工作树、一个构建目录（`build-<字母>`）。先定接口的那一路先做，交回复审后再放并行的几路，最后一个集成子会话合并、走接缝、备试玩存档。
- 施工简报要写全：背景与已定的事、硬约束（第 2 节第 8 条）、文件归属（谁能改哪些文件）、做完的样子、要交回什么（提交哈希、测试条数、截图、拿不准的地方）。子会话看不到主会话的对话。
- 让每一路写一份施工记录（`docs/<名>-<路>.md`），末尾列「拿不准的地方」和「留给集成的事」。主会话逐条裁定。
- 审的时候自己看：提交与差异、测试日志的结论行、工作区是否干净、换行符（见第 8 节）、截图、每一句对白。子会话的汇报不算证据。
- 全量 ctest 跑着的时候不要改数据文件：测试读的是仓库里的真数据，中途改会把正在跑的用例弄红。
- 工作树的 `vendor/` 是指向主检出的目录联接。**删工作树之前先解除联接**（`rmdir` 那个联接本身），否则递归删除会顺着联接删到主检出的 `vendor/`。

## 8. 环境上的坑（Windows）

- 本仓库 `.gitattributes` 是 `* -text`。如果本机 `core.autocrlf=true`，合并冲突的文件和 Python `open(p, 'w')` 写出的文件会变成 CRLF。提交前对一下 `git diff --stat` 与 `git diff --stat --ignore-cr-at-eol`，两个数不一样就是换行符被改了。Python 写仓库文件一律 `newline=''`。
- 从 bash 里调 `cmd.exe` 可能假报成功：看日志里的 `BUILD_DONE`、`CTEST_EXIT=0`，不要只看退出码。
- bash 工具会把命令里的 `\\` 吃成 `\`：带反斜杠的脚本用写文件的工具写出来再跑。
- 用户目录带特殊字符（比如撇号）时，`.bat` 放在仓库目录下，不要放用户目录。
- 地图一律用 `python tools/mapgen/genmaps.py --sync` 落盘；单跑某一章的生成脚本会抹掉后几章补在同一张图上的对象。
- 旧电脑没有配 git 身份，提交用的是 `git -c user.name=zhishouhuameiwan -c user.email=<该账号的 noreply 地址> commit …`。新电脑按自己的情况配。

## 9. `art-sources` 分支怎么更新

它只是一份快照，不需要历史。源图有增改时，在有源图的电脑上、仓库根目录：

```bash
git fetch origin art-sources
export GIT_INDEX_FILE="$(git rev-parse --absolute-git-dir)/art-sources.index"
rm -f "$GIT_INDEX_FILE"
git add -f -- fanren/docs/heroine-art fanren/docs/companions-overhaul
git ls-files | grep '_metadata\.json$' | xargs -r -d '\n' git rm --cached -q --
git update-index --add --cacheinfo "100644,$(git rev-parse origin/art-sources:ART-SOURCES.md),ART-SOURCES.md"
tree=$(git write-tree)
rm -f "$GIT_INDEX_FILE"; unset GIT_INDEX_FILE
commit=$(git commit-tree "$tree" -m "art: 美术源图快照（<日期>）")
git push --force origin "$commit:refs/heads/art-sources"
```

- 这一串用的是临时索引，不碰工作区和 main 的暂存区。2026-11-21 在旧电脑上照着跑到 `write-tree` 为止，得到的树与已推送的那一份逐字节相同。
- 出图服务写的 `*_metadata.json` 里有带签名的临时下载链接，**不要上传**（第五行就是把它们拿掉）。
- 第六行把分支根的说明 `ART-SOURCES.md` 原样带上。
- 上传前扫一遍文本文件（提示词、脚本），确认没有密钥。
