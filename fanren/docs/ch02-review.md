### 对作者自查数字的核对

作者自报「对 ch10-27 全文最长重合 7 字、10 字及以上 0 条」。

- **「10 字及以上 0 条」属实**，而且我用的是**全本**基准，比作者的 ch10-27 基准严得多，仍然是 0。这条可以采信。
- **「最长 7 字」不准，实测 8 字**（`ch02.renyao.guanshi_last` 的「该干什么干什么去」）。差异来源是基准范围：该片段不在 ch10-27 内，`novel.py find "该干什么干什么去"` 在全本的 `total_matches` 也是 0——因为它跨了标点，只有剥标点后的连续检索才抓得到。**结论：作者的数字没错在算法上，错在基准只取了 ch10-27。后续章节请一律对全本跑。**

### 但是：机器口径合格 ≠ 这一项合格

**上面两道口径全过，我仍然认为这一项不合格，并且这是本章与第 1 章差得最远的一项。**

「**写出的句子若放回原著几乎看不出差别，重写**」「不得摘抄、**转写**或"改几个字"地复制原著语句」。

#### BLOCKER-1：`take()` 的年份参数被引擎丢掉，章末算账扣错药材，且留下重复变现的口子

**位置**：`src/game/Application.cpp:273-276`（`CommandKind::TakeItem`）
`scripts/ch02/suanzhang.lua:34, 39`、`scripts/ch02/maiyao.lua:26`

**事实**：`scripts/common/api.lua:119` 的 `take(item_id, count, herb_age)` 把年份放进命令的 `y`，
但 dispatch 里写的是：

```cpp
case CommandKind::TakeItem:
    outcome.ok = state_.removeItem(command.a, command.x <= 0 ? 1 : command.x);

```

`command.y` 从头到尾没被读。而 `GameState::removeItem`（`Types.cpp:70-73`）明写
「**先扣年份低的，把高年份留给玩家**」。于是章末那场算账：

take("herb_huangjing_cao", 1, 11)   -- 想扣十一年份的
give("material_lingshi", 22)
take("herb_huangjing_cao", 1, 44)   -- 想扣四十四年份的
give("material_lingshi", 145)

> 必须按年份精扣这一堆。走 `GameState::removeItem` 会先扣年份最低的那堆——

#### MEDIUM-2：章末的「瓶颈」台词与实际机制相反

**位置**：`data/text/ch02_main.json` 的 `ch02.suanzhang.bottleneck` / `bottleneck2`，
连带 `docs/ch02-design.md` 第 3 节「本章的收益封顶」那张表

台词说的是：

> 「八畦地一年就出这么几株，瓶子却七天凝一滴，**凝出来的多半没处使**」
> 「**缺的从来不是那点绿液，是地，是年头**。八畦太小了」

设计第 3 节的算法是「灵田一年长 1 年份 → 等足年 → 三滴推到 44」，据此得出瓶颈是槽位与生长时间。
**但引擎允许对 `age = 0` 的苗直接催熟**（`matureHerb` 只查 `currentAge >= ceiling`，不查是否足年；
`FieldScene::matureAt` 也不查 `ripe`，催完还会顺手把 `ripe` 置真）。实算：

| 路线 | 滴数 | 需等的生长时间 |
| --- | --- | --- |
| 等足年（1 年）再浇：1 → 11 → 22 → 44 | 3 滴 = 21 天 | **360 天** |
| 刚种下就浇：0 → 10 → 20 → 40 → 44 | 4 滴 = 28 天 | **0 天** |

多花 1 滴（7 天）省掉 360 天，**等足年是被严格支配的劣策**。于是真实的产能是
「51 滴/年 ÷ 4 滴/株 ≈ 12.75 株/年」，**与槽位数无关**（8 槽或 16 槽都一样，因为绑住的是绿液流量），
也与生长时间无关。绿液**一滴都不会剩**，恰恰是唯一的闸。

收益量级倒是没崩（12.75 × 145 ≈ 1850，对照设计估的 1160，同一量级，不必调平衡），
**但台词的内容是错的**，而且是当着玩家的面错：他刚刚才在面板上对一株 0 年的苗浇过绿液。
顺带地，脚本注释里「这两句同时是第 6 章接手百药园的引子：那边的解法就是槽位更多、长得更快」
这个引子也就接不上了——槽位更多解决不了任何问题。

**建议**：要么改台词（把瓶颈说成「瓶子七天才凝一滴，地闲着也没用」），
要么改规则（`matureAt` 拒绝未足年的槽位，让设计第 3 节的算法成立）。
**我倾向改规则**：「不足一年的不准动手，采下来就是废的」这条规矩是 `ch02.renyao.guanshi_rule` 当着玩家立的，
让绿液绕过它本来就说不通，而且改完之后「攒满一瓶浇一株」才真正成为最优解，本章的教学才立得住。
这一条要连 `docs/ch02-design.md` 第 3 节一起裁。

**位置**：`scripts/ch02/ceng2.lua:19-27`、`maps/ch02_jusuo.tmj` 的 `trigger_ceng2`

`ch02.ceng2.hint`「外刃堂那边前些天捎过话来，说厉师兄找他」也会因此变成马后炮。

**建议**：给 `renqing.lua` 开头加一道 `if flag.get("ch02.koujue_ceng") < 2 then talk(...gate) return end`，
或给 `trigger_ceng2` 加 `guard_flag = ch02.duan4_start` 并在 `ceng3.lua` 里补 `koujue_ceng >= 2` 的前置。
**顺带**：地图上 `trigger_ceng2`（打坐处旁）与 `trigger_ceng3`（床边）同处一室，两者的可达性我都验过，
玩家在段五先碰到哪个纯看走位，不能靠「一般人会先走到哪」来兜。

## 附：这一章作为「核心循环第一课」做得怎么样

**先说它比第 1 章强在哪：交付的完整度不是一个量级。**

第 1 章的两处阻断（旗标塌陷、传送点无门槛）这一章一个也没重演，而且是**有意识地**没重演：
`Application.cpp:255` 的 `SetFlag` 注释里原话是「在这里把 0 改写成 1，只会让脚本永远无法显式清掉一个旗标」，
`WorldScene::triggerReady` 把 `guard_flag` 判在 `once` 记号之前，
三个传送点全挂了 `require_flag` 并配了 `deny_text_key`——第 1 章报告里点名的每一件事都做了。
281 条文案零孤儿零缺失、旗标零悬空，这种干净程度在内容量翻了一倍半之后还能保住，值得记一笔。

**再说它最好的地方：它真的没有用旁白解释机制。**

六块 → 二十二 → 一百四十五，三个数摆在柜台上，中间隔着四年，没有一个人告诉玩家这意味着什么。
`ch02.suanzhang.compare`「一堆二十二，一堆一百四十五。旁边空着的那块地方，是四年前那六块」——
**空着的那块地方**，这一笔比任何教程都狠。`ch02.suanzhang.count` 收尾在「这话没人教他，他自己看出来的」，
药商全程只报价不讲道理，`ch02.npc.yaoshang_3` 那杆「小秤 / 大秤」的伏笔在章末真的被抬了出来。
**设计文档第 3 节要的「玩家自己算明白，不是靠旁白告知」，编剧这一侧做到了。**

**问题出在：玩家算的那笔账，游戏自己没有记。**

他数着纹路从 11 数到 22 再到 44，把三滴绿液「浇」在同一株上，然后走到柜台前，
看着药商起身进屋搬大秤——这一整段做得很好。而在同一时刻，他的瓶子是 3/3 满的，
他的背包里那株四十四年份的黄精一直在，被扣掉的是一株刚发的种苗。
**这一章最好的一场戏，和第 1 章一样，是被实现层吃掉的。**
区别只在于第 1 章吃掉的是情绪支点，这一章吃掉的是经济支点——
而经济支点是全作的中枢，它错在第 2 章，后面十四章都得跟着错。

还有一处更可惜的：`shiyao.lua` 里那段「恒为假」的守卫，作者写了**一整段穷举证明**贴在注释里，
证明是对的（我用两条独立方法确认过）。**他离答案只差一步**——那个证明顺着往下推一行就是
「所以整章走完绿液还是 3」，也就是 BLOCKER-2。他证明了前半段，没问后半段。
这和第 1 章的教训是同一个：**验在文档上、验在注释里，就是没验在跑起来的代码上。**

所以我对这一章的判断和第 1 章形态相似但成因不同：
**第 1 章是"写完了没验"，这一章是"验了，但验的是自己的推理，不是程序的行为"。**
两者的解药是同一条，而且设计文档第 8 节自己已经写下来了——
「靠人工点一遍不作数，必须是能重复跑的测试」。那条测试没写。
**先把它写了，上面三条 BLOCKER 里有两条会当场红给你看。**

   这**正好是我本来要提的那个问题，而且他们先提了**。

## 附录 B2：一句给下一章的话

上一轮的诊断是「**验了，但验的是自己的推理，不是程序的行为**」。这一轮把那句话正面回答了：
`TheScannerItselfHasTeeth`、`TheBagVerdictRefusesAnEmptyBagInsteadOfWavingItThrough`、
`TheImmortalPanelIsExactlyWhatWouldHaveFailedTheScan` —— 三条用例做的都是同一件事，
**先证明判据咬得动人，再拿它去验真实的运行结果**。这是这个项目三章以来第一次有人把这件事当成交付物。

而 N1 恰好是它的反面：`maiyao.lua` 那四行注释把道理讲得再清楚不过（「静默失败在本项目是明令禁止的」），
**同一个文件夹里两笔大十倍的交易却没照做**。纪律写在注释里、写在一个调用点上，都不算数；
要么写成判据（一条测试扫全部 `take()` 调用点），要么就会像这次一样，修完一个洞、旁边还留着一个。

**下一章的建议只有一条**：把「凡 `take()` / `item.count()` 的返回值必须被使用」做成 `tools/validate.py`
的一条静态检查。本章这两个洞（`maiyao` 修了、`suanzhang` 没修）会在那条检查下同时亮红，
而且以后每一章都不必再靠人去发现它。
