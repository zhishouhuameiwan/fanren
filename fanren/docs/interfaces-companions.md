## 1. 名词

| 词 | 意思 |
| --- | --- |
| 伙伴 | 能入队、有头像、会说话的人。数据在 `data/companions/` |

## 2. 数据

### 2.1 `data/companions/<id>.json`

```jsonc
{
  "id": "nangong_wan",
  "roles": [                                   // 这个人用过的全部角色 id，按先后
    {"role": "baiyi_shaonv", "until_flag": "ch07.nangong"},
    {"role": "nangong_wan"}
  ],
  "met_flag": "ch07.nangong",                  // 置了就进名册
  "field_skill": "break_seal",                 // 场地技；没有就不写
  "chase": true,                               // 能不能追击
  "duo": "duo_nangong_zhuque",                 // 合招，是 data/magics 里的一条
  "gifts": {"like": ["..."], "dislike": ["..."]},   // 物品 id；没列的算寻常
  "note": "原著同行窗口与依据，带章号"
}
```

**`party` 里存的仍然是角色 id，这一点不改。** 主线脚本照旧写 `party.add("baiyi_shaonv")`。伙伴数据只多做两件事，各收在一个函数里：

- `companionOfRole(角色 id)`：这个角色属于哪位伙伴。默契、追击、合招、场地技、插话的 `require_party`、一人一身都经它查。
- `currentRole(伙伴 id)`：现在该用哪个角色 id——`roles` 里第一条 `until_flag` 没置的。只有历练组队和主菜单名册页调用它。另许可一处：机关提示「这里要某某来」时她不在队里，取她的名字只能经它。她在队里时，一律用队伍里存的那个角色 id。

`roles` 要按时间把每一段都列全。**历练里用的就是 `currentRole` 给的那一个**，所以每一段的角色表都得是「那时候的她」：名字、境界、会的东西都对。南宫婉问名之后、第 7 章结束之前这一段，现成的两份角色表都不对（一份名字不对，一份是第 8 章以后的境界、还不会朱雀环），要新建一份，见样板施工图第 9 节。

不在任何伙伴 `roles` 里的队员（现有的傀儡、化身、曲魂）不是伙伴，下面的规则都不碰它们。**P1 不给它们补伙伴数据。**

### 2.2 默契

| 档 | 名 | 阈值 | P1 实现的解锁 |
| --- | --- | --- | --- |
| 1 | 初识 | 0 | — |
| 2 | 相熟 | 20 | 追击 |
| 3 | 默契 | 45 | 无（P3 定） |
| 4 | 知己 | 70 | 合招 |
| 5 | 同心 | 95 | 无（P3 定） |

来源（初值）：

| 来源 | 加多少 | 限制 | 谁来加 |
| --- | --- | --- | --- |
| 并肩打赢一仗 | +2 | 同一位伙伴每天至多 +6 | 战斗结算，引擎加 |
| 赠礼 | 合意 +5 / 寻常 +2 / 不喜 0 | 每人每天一次 | 主菜单队伍页「赠与」，引擎加 |
| 剧情里的默契事件、插话 | 脚本写多少是多少 | 脚本自己保证只演一次 | 脚本 `bond.add(id, n)` |

默契只增不减，封顶 100，离队不清零。

**记账只有一处**：`src/core/rules/Companions.*`。「并肩打赢」的每天上限、赠礼的每天一次和合意 / 寻常 / 不喜怎么算，都是那里的函数；战斗结算（B 路）和赠礼（D 路）只调它们，不各写一套。不喜的礼加 0，但也算当天送过了。打赢一仗，上过场的伙伴都记，中途倒下的也算。赠礼只能送给队伍里的伙伴，剧情物不可送；今天送过了，东西不扣、账不动。

### 2.4 地图与编成的新东西

**四种新对象：**

| type | 必填属性 | 可选属性 | 行为 |
| --- | --- | --- | --- |
| `chest` | `id`、`loot` | `require_flag` | 开一次，记档。占格 |
| `gather` | `id`、`item`、`respawn_days` | `require_flag` | 采一次进冷却，按日历刷新。占格 |
| `foe` | `id`、`battle`、`look`、`facing` | `respawn_days`（缺省不重生）、`elite`、`require_flag` | 见 3.4。占格，不走动 |
| `gate` | `id`、`skill` | `opens`（打开后置的旗标，剧情或别的门要读它时才写）、`hint` | 见 3.6。占格，开了之后不占 |

对象 id 全局唯一，以图名作前缀。

`loot` / `item` 写成 `物品id` 或 `物品id:件数`，多样用逗号隔开。`chest` / `gather` / `foe` 的 `require_flag` 没置时，这个对象就当不在（不画、不占格、按了不响）；`gate` 不收 `require_flag`。`gate.hint` 是一条文案 key，替换「似乎要用别的法子」那一句。

**三处小扩展：**

- `trigger` 多一个可选属性 `require_party`，**只收伙伴 id**：这位伙伴（不论当时用的是哪个角色 id）不在队里就不触发。给插话用（3.8）。不收角色 id——`nangong_wan` 既是伙伴 id 又是她后期的角色 id，两种都收会有歧义。
- `facility` 多一种 `kind: "lilian"`，带 `site`（历练地 id）。历练的入口（3.12）。
- 战斗编成多一个可选字段 `scale_by_party`（缺省 `false`）。见 3.10。

### 2.5 头像与高清人物表

- `data/visual/portraits.json`：角色 id → 头像图集与表情帧（`normal` / `smile` / `angry` / `hurt`）。同一个人的不同装束登记成不同角色 id 的条目（白衣女子戴面纱那一套挂在 `baiyi_shaonv` 上）。没登记的角色对白照旧不带头像。
- 人物表新增四个**按表**的字段。缺省值就是现在的行为，旧表一个字不用改。

  | 字段 | 意思 | 缺省 | 高清表 |
  | --- | --- | --- | --- |
  | `scale` | 世界层按几倍画 | 3 | 2 |
  | `walk_cycle` | 走路播放序（每一向帧表的下标） | 索引顶层那一份，`[0,1,0,2]` | `[0,1,2,3]` |
  | `battle_scale` | 战斗层按几倍画。首领在它上面「加四分之一、取整」（4 得 5，2 仍是 2） | 4 | 先取 2（132×84 的格里人高约 64 像素，×2 是 128；旧表战斗人高约 92） |
  | `battle_sheet` | 战斗帧在另一张图上时写。是一个对象：`file`、`frame_w`、`frame_h`、`cols`、`foot_y`、`head_y`，**六项全写** | 不写 = 战斗帧与走路帧同一张图、同一套格子 | 写 |

  写了 `battle_sheet`，`battle` 帧表里的帧号指的就是那张图上的格子。战斗图的格子和走路图差得很远（定稿美术：走路格 64×60，战斗格 132×84、脚底在第 82 行），所以不能只给一个文件名、几何还借走路图的——底座第一版就是这样写的（`battle_file`），验收时改掉。取战斗帧的文件、矩形、脚底、头顶都经 `SpriteAtlas` 里的函数，别处不自己判「有没有 `battle_sheet`」。
- 具名角色的手绘表放 `assets/art/sprites/hd/`，**另有一份自己的 `hd/index.json`**，人工维护。加载时先读程序生成的 `sprites/index.json`，再用它覆盖同名角色；这个文件不在就什么都不做。`artgen.py --check` 只管它自己生成的那份。形状：

  ```jsonc
  {
    "sheets": {"nangong_wan_ch07_hd": { /* 与生成索引里的人物表同形 */ }},
    "roles": {"baiyi_shaonv": "nangong_wan_veil_hd"},          // 角色 id → 表 id
    "role_variants": {"hanli": [{"look": "hanli_child", "max_chapter": 2}]},   // 可不写；与生成索引同形
    "files": {"nangong_walk.png": "<sha256>"}
  }
  ```

  - 表里的 `file`（含 `battle_sheet.file`）相对 `hd/`。
  - 手绘表**必须自己写 `scale` 和 `walk_cycle`**，漏了整份报错——继承缺省的话是 ×3、第 4 帧永远播不到，而且不报错。
  - 手绘表的 id 不许与生成的表同名：覆盖的是角色，不是表。
  - 覆盖一个角色时，它在生成索引里的按章变体不再作数（否则先看变体，覆盖等于没覆盖）。还要按章换的，在 `hd/index.json` 自己的 `role_variants` 里写；那里的 `look` 可以指手绘表，也可以指生成的表——韩立第 1–2 章的少年相在手绘版画出来之前，就这样接着用生成的那张。
  - sha256 由门禁核（第 5 节），加载器只认形状。
  - `role_variants` 里写了哪个角色，就替换掉生成索引里那个角色的变体——不管它在不在手绘索引的 `roles` 里。
  - `battle_sheet` 里写了六项之外的字段也整份报错。
  - **待补（四路合并之后）**：`hd/index.json` 现在只管人物表。墨蛟、碧水鳄这类非人形敌人的手绘图在生成索引的 `enemies` 里，手绘索引覆盖不到。合并后在底座的加载器里补上：`hd/index.json` 可带 `enemies`（与生成索引同形，`file` 相对 `hd/`），覆盖同 id 的敌人、也可以新增；非人形敌人的倍数现在是写死的（世界层 ×3、战斗层 ×4 / 首领 ×5），手绘的大图要能自己写倍数。

## 3. 规则

### 3.1 谁上场

- **不是伙伴的队员**（傀儡、化身、曲魂等）：照现在的规矩，`active` 的全部上场，不设上限。第 8–12 章带着它们的仗一点不变。
- **伙伴**：`active` 的前 3 位上场，第 4 位起不上场。
- `active` 只能在主菜单「队伍」页里改；不给脚本开口子。
- 只有队伍里带进来的人才算伙伴：编成里写死的友军即使角色属于某位伙伴，也不参与追击、合招和默契。
- 队伍面板 4 人起每多一人高一行，最多 6 行；第 7 人起不显示（非伙伴的队员不设上限，但现有的仗最多 6 人）。

### 3.2 追击

- **触发**：我方任何一次出手（普攻、法术、道具、符）让某个敌人**进入破势**。
- **谁追**：
  - 出手的是韩立 → 场上的伙伴里，默契 ≥ 二档、`chase` 为真、没倒下、本回合还没追击过的，取默契最高的一位（并列取队伍次序靠前的）。
  - 出手的是伙伴 X，且韩立与 X 的默契 ≥ 二档、韩立在场且没倒下 → 韩立追（韩立每回合也至多追一次）。
  - 伙伴之间不互相追击。不是伙伴的队员不参与。
- **追什么**：对那个刚进入破势的敌人补一记普攻，按追击者自己的兵刃类别。不占行动、不耗劲、不能蓄劲，吃破势的伤害加成。
- **一次出手打出多个破势**（群攻）：只对第一个进入破势的目标追击一次。
- 追击不再触发追击。
- 群攻里第一个进入破势的敌人，如果同一手里已经被打倒，就不追，也不改去追第二个。
- 合招那一手不触发追击（见 3.3）。

### 3.3 合招

- **条件**：默契 ≥ 四档；发起人轮到自己行动；另一位没倒下、本回合还没行动过；两人各有 2 点劲。
- **发起人**是在自己回合里选「合招」的那一位（韩立或伙伴 X 都可以）。
- **代价**：两人各扣 2 点劲；两人本回合的行动都算用掉；两人都算「本回合蓄过劲」，下一回合开始不加劲（与现有 2.3 的规矩一致）。
- **效果**：`duo` 指向的那条法术，由发起人施放——境界压制、「只有某类要得了命」、事件归属都算发起人的。威力乘 1.6。不能再叠蓄劲。
- **合招这一手不触发追击**：两人都已经出手，合招本身就是那次联手；场上另有第三位伙伴也不追。
- 代价只有劲：不扣法力，也不查发起人会不会这门法术、境界够不够。陪同的那一位如果摆着守势，守势当场散掉。
- 菜单：「合招」是根菜单第六项、排在逃跑之后，只在有合招可出的仗里出现（没有伙伴的仗，菜单与从前逐行相同）；出现之后条件不够就置灰并写明理由。点进去先挑与谁合。
- 测试用的那只手（`BattleHand`）要能经真实菜单选合招，不许直接调规则层（教训 16）。

### 3.4 明雷

- `foe` 占一格，站着不动，面朝 `facing`。
- **被它看见**：主角踏进它面前那一格，直接开打，不加不减。
- **偷袭**：主角站在它的侧面或背后相邻格，面朝它按确认键，开打并占先手——我方全员开场多 1 点劲，且第一回合我方全员排在所有敌人之前行动。多出来的 1 点劲意味着第一回合就可能出合招，这是有意的，是绕背的奖励。
- 先手是行动序里的一个新键（现有的先手只有「防御」给的那一种），接在哪见第 4 节。战斗场景只在 `Application::battleStart().battleId` 与自己这一场的 id 相同时才认先手；这个 id 必须是**实际压栈的那个**（历练里是拼过档后缀之后的），`startBattle` 要保证两处用同一个。
- 打赢：这个 `foe` 消失并记档；有 `respawn_days` 的到日子重新出现。
- 打输：按编成自己的 `defeat_is_fatal`。**明雷的编成一律写 `false`**，败了回到这张图的缺省出生点（地图上本来就有，不用另存）。
- `elite` 的不能逃。逃跑成功：`foe` 留在原地，主角退回开打前站的那一格。
- 在历练里打输，以 3.12 为准（整趟退出）。
- 触发的先后：被明雷看见排在踏入触发器、传送点之前。所以明雷面前那一格不许与传送点、踏入式触发器、别的新对象重叠（门禁查）。只有「迈进」面前格才算被看见——读档、逃跑退回、传送落在那一格都不开打。
- 站在它面前那一格按确认是普通开打（不占先手）。敌人自己跑了：明雷和主角都留在原地。

### 3.5 宝箱与采集

- 宝箱开过就一直是开着的样子。采集点冷却中显示成采过的样子。
- 背包没有容量上限；这里的「满」指某一堆再加就超过 999 件。这时开不了、采不了，给一句提示，对象状态不变。

### 3.6 机关与场地技

- 面朝 `gate` 按确认键。队里任意一位伙伴的 `field_skill` 等于 `gate.skill` → 播一小段演出，记进「已开机关」（2.3），此后不占格；写了 `opens` 的再置那面旗标。
- **历练图上的机关不许写 `opens`**：旗标是永久的，写了第二趟进去它就是开着的。历练里机关开没开只记在这一趟里。
- 没人会：名册里已有会这手的人 → 提示「这里要某某来」；名册里还没有 → 提示「似乎要用别的法子」。
- **主线必经的路上不许放 `gate`。**
- **放了 `gate` 的图，必须是玩家带着会这手的伙伴走得到的图。** 只进不出、她又还没入队的图上不许放（那样的机关永远打不开）。门禁只查得了一半：会这手的伙伴里至少有一位的 `met_flag` 是拿得到的；「她在队时那张图还回得去」查不了，由施工图保证。
- 场地技、`require_party`、一人一身说的「在队里」，不上场（`active` 为假）的伙伴也算。

### 3.7 跟随

- 上场的伙伴排成一列跟在主角身后，各隔一格，走主角走过的格子。不占格、不踩触发器、不挡 NPC。
- 换图、剧情传送、读档之后，足迹清空，伙伴叠在主角格上，走一步才排开。
- 不是伙伴的队员（傀儡等）P1 不跟随，与现在一样不显示在图上。
- 足迹还不够长时，排不开的伙伴叠在最后一格上。

### 3.8 插话

- 就是一个普通的踏入触发器，带 `require_party`，挂一小段脚本：一两句 `talk`，末尾 `bond.add`。会停下来，和现在的对白一样。
- 一格只能挂一个触发器，这条老限制照旧。
- 脚本新增三个函数：`bond.add(伙伴 id, n)`、`bond.get(伙伴 id)`、`bond.tier(伙伴 id)`。

### 3.9 对白头像

- `talk` 加一个可选的表情参数，缺省 `normal`。现有脚本不用改。
- 说话的角色在 `portraits.json` 里有头像就画在对白框左侧，没有就照旧。
- 头像表的形状、放大规矩（放得进 128×144 的最大整数倍；定稿的头像原生约 100–131 宽、86–136 高，打包成 128×136 的格子、按 ×1 画——先前写的「56×64 得 ×2」是把尺寸读错了）。头像表里一个角色挂一张按章的列表（`min_chapter` / `max_chapter`，与 `role_variants` 同一种判法），取第一条成立的、正文右移「头像宽 + 20」，写在 `docs/art-sprites.md` 5.3。四个表情在表里必须都写；脚本写了认不出的表情按 `normal` 画。对白框排不下的正文是直接截断的——A 路按带头像的宽度量过 1235 句写死说话人的台词，装不下的是 0 句（检查在 `tests/PortraitTextFitTests.cpp`）。
- 主菜单的小像：倍数取每张表 `scale` 的 4/3 取整（旧表 3 得 4，高清表 2 得 2），画的时候按脚底对齐，左、右、下严格裁到小像框内，上边最多高出框 16 像素——曲魂这类 24×32 的旧表按 ×4 画一直就比框高出 12 像素，现有画面要保住。队伍、名册两页只在名册上有人时出现。

### 3.10 人数系数

- 编成写了 `scale_by_party: true` 才生效：敌方气血按我方上场人数乘系数——1 人 ×1.0，2 人 ×1.35，3 人 ×1.7，4 人及以上 ×2.0。架势不乘。
- 缺省是 `false`。**现有 71 份编成没有这个字段，一场都不受影响。**只有新写的明雷和历练编成会用它。
- 「我方上场人数」把韩立、编成里写死的友军和队员都算上。

### 3.11 一人一身

- 只对伙伴生效：某位伙伴的任意一个角色 id 在 `party` 里时，地图上 `role_id` 属于这位伙伴的 NPC 对象不显示、不可交互。收在 `visibleNpcAt` 一处。
- **这条门禁查不了**——谁在队里是脚本里 `party.add` 定的，不是旗标。所以不设门禁规则，靠这一处守卫，加上每章一条走真入口的用例（她在队里时，图上没有第二个她）。
- 不是伙伴的队员不受影响，第 10 章化身既是 NPC 又入队的现状不变。

### 3.12 历练

| 项 | 规则 |
| --- | --- |
