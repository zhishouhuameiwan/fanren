# 第 7 章可玩性改版·第一期「地基包」施工图

> 2026-11-20。上位文档：`docs/gameplay-overhaul.md`（方向与拍板记录）。
> 本期只做三件事：**指引、物品与法术说明、对白减负**。伙伴、法器、战斗规则留给第二、三期，本期不碰。
> 分工：主会话只写施工图和审核；施工由三个并行子会话各在自己的工作树里做（路 G、路 M、路 D），之后由一个集成子会话合并。

## 0. 用户原话与本期目标

用户 2026-11-20 第二轮试玩后的原话：

> 还是感觉可玩性不高，各种信息指引不够，物品说明也不够，对话又很多

本期要让玩家：

1. 任何时候看一眼屏幕就知道**现在做什么、去哪儿、还差多少**。
2. 拿到任何一样东西都知道**它有什么用、数值多少、哪儿来的**。
3. 两次动手之间**不用连按十几下确认键**。

## 2. 路 G：指引

### 2.1 目标框两行式

**数据**：`core::Objective` 加三个可空字段。

| 字段 | JSON 键 | 作用 |
| --- | --- | --- |
| `hintKey` | `hint_key` | 要点，小字一行，至多 28 个字 |
| `detailKey` | `detail_key` | 详情，只在记事里显示。放现在的长句，文案不丢 |
| `progress` | `progress` | 进度，显示成「1/3」接在行动句后面 |

`progress` 三种写法：

```json
{"kind": "item", "item": "herb_x", "need": 3}
{"kind": "aged_item", "item": "herb_huangjing", "min_age": 44, "need": 3}
{"kind": "flags", "flags": ["a", "b", "c"]}
```

**内容**：`data/objectives/ch07.json` 的 50 步全部重写。

- `text_key` 改成行动句：动词开头，写清对象和地点，至多 16 个字，不剧透。
- 现在的长句改挂到 `detail_key`。
- 有窍门或前置条件的加 `hint_key`。
- 要凑数量的加 `progress`。

口径示例（前三步）：

| 步 | 现在 | 行动句 | 要点 |
| --- | --- | --- | --- |
| n01 | 回屋把叶师叔送来的那只包拆开 | 回屋拆开叶师叔送的包 | — |
| n02 | 苗先下到药田，满一年才浇得进。黄精要四十四年——……够了三株，放进茅屋前的药篓 | 催熟黄精 0/3，放进药篓 | 用绿液浇到 44 年；绿液不够去蒲团打坐 |
| n03 | 紫参要百年，一株五滴。两株够了，再往药篓里放 | 催熟紫参 0/2，放进药篓 | 紫参要 100 年，一株约五滴绿液 |

**画面**（`WorldHud` 的目标框）：

- 行动句用现在的字号；要点行小一号、暗金色；「前往」行保留。
- 目标换了的时候框闪一下，响一声现有的提示音。
- 没有 `hint_key` 的步骤（别的章）画面与现在一致。

### 2.2 跨图指路

「前往 X」现在只写下一道门。改成写**最终去哪、先过哪**：「前往　巫钧山（经黄枫谷北阵门）」。

- `rules::nextPortalToward` 旁边加一个返回整条路的函数，纯函数，带单测。
- 目标就在本图时不写「经」。

### 2.3 教学卡

**数据**：`data/tutorials/ch07.json`。

```json
{
  "id": "tutorials_ch07",
  "cards": [
    {
      "id": "boost",
      "title_key": "tutorial.boost.title",
      "body_keys": ["tutorial.boost.l1", "tutorial.boost.l2"],
      "trigger": "battle_boost_available",
      "min_chapter": 7,
      "max_chapter": 7
    }
  ]
}
```

- `body_keys` 至多三行，每行至多 30 个字。
- `trigger` 是引擎事件名；为空表示只由脚本 `tutorial("id")` 触发。
- 引擎事件由你按需要定义，例如：进入战斗、敌人有未揭开的破绽、可以蓄劲、明雷进入视野、站到明雷侧背、靠近宝箱或采集点、打开灵田、打开炼制面板、名册第一次有人、遇到机关。

**行为**：

- 一块小面板：标题、至多三行、按键提示。确认键关掉。
- 每张只弹一次，用旗标 `tutorial.seen.<id>` 记。
- 战斗里弹的时候战斗输入暂停。
- 过场对白进行中不弹，等对白结束。
- 设置里「教学提示」关掉后不再弹，但照样记为看过，记事的「指南」页里照样能翻。
- 无头测试里不能卡住通关验收：给测试一个关掉它的办法。

**第 7 章至少要有这些卡**（14 张起）：破绽与架势、蓄劲、防御换先手、偷袭明雷、明雷追击与绕行、宝箱采集与收集进度、小瓶绿液、交药看年份、打坐回气、炼丹成功率、伙伴上场与默契、赠礼、机关与场地技、道具施法、战斗外用药、地图键与记事键。

每张写之前先在代码里核对规则，数字要和引擎一致（例：蓄劲上限、偷袭给几点劲）。

### 2.4 记事分四页

`BoardScene` 改成四页，左右键或肩键翻页，手柄提示同步。

| 页 | 内容 |
| --- | --- |
| 主线 | 上半截「眼下」：行动句、要点、详情长句、地点。下半截：做过的步骤，倒序 |
| 支线 | 进行中、已过期、已了结。选中后右侧写摘要、当前步骤、**奖励**（读 `Quest.rewards`，物品名 × 数量）。收掉技术债 G-25 |
| 指南 | 看过的教学卡，选中重看 |
| 见闻 | 见 2.5 |

### 2.5 见闻

**数据格式在这里定死，路 D 照这个格式写内容**：`data/lore/ch07.json`。

```json
{
  "id": "lore_ch07",
  "chapter": 7,
  "entries": [
    {
      "id": "jindi_wuri",
      "category": "shijian",
      "title_key": "lore.ch07.jindi_wuri.title",
      "body_key": "lore.ch07.jindi_wuri.body",
      "unlock_flag": "ch07.xxx",
      "role_id": ""
    }
  ]
}
```

- `category` 四种：`shijian`（所闻：设定、规矩、来历）、`yaoshou`（妖兽）、`lingcao`（灵草与丹药）、`renwu`（人物）。
- `unlock_flag` 置位即解锁；空串表示一开始就有。
- `role_id` 只给妖兽条目用：页面自动补一行**已知破绽**（存档里的 `knownWeaknesses`）和**掉落**（`data/battles` 里它的 `rewards.drops`）。
- 文案放 `data/text/ch07_lore.json`。标题至多 10 个字，正文至多 120 个字。
- 新解锁时屏幕上提示一条「见闻：XXX」，不挡路、不用按键。

**归属**：读取、规则、页面、提示归路 G。条目内容归路 D。路 G 先写 3–5 条妖兽条目把页面跑通，文件里留给路 D 往后追加。

## 4. 路 D：对白减负

### 4.1 删减

**范围**：`scripts/ch07` 的 56 个 Lua；`data/text` 的 `ch07_main`、`ch07_jindi`、`ch07_dihuo`、`ch07_companions`、`ch07_e2`。

**两个指标**：

| 指标 | 现在 | 目标 |
| --- | --- | --- |
| 主线对白字数（口径同 `ch07-design.md` §14） | 17,501 | 9,000–10,000 |
| 两次可操作之间连续 `talk` 的最大句数 | 未量 | 不超过 8 |

「可操作」指选择、战斗、走图、打开面板。先写一个统计脚本或单测量这两个数，交付时给每个脚本改前改后的对照表。

**手法**，按顺序用：

1. 删重复的话、寒暄、复述上一句的话。
2. 讲设定、讲规矩、讲来历的话挪走：写成见闻条目（格式见 2.5），或做成那个 NPC 的可选「打探」（`data/pathactions/ch07.json`）。
3. 几句短话并成一句。
4. 旁白能用走位、停顿、表情交代的，换成演出。
5. 还超过 8 句的长戏：中间给玩家一步操作，或拆成前后两场。

**不许动**：

- `give`、`take`、`flag.set`、`battle`、`realm.advance`、`magic.learn`、`magic.forget`、`party.add`、`party.remove`、`bond.add`、`teleport`、`advance_days`、`choice` 的集合、参数和相对顺序。
