# 音频：程序合成的 BGM 与音效

> 2026-09-25 · 八方旅人化改造 · 音频路 · 生成器 `tools/audiogen/` · 产物 `assets/bgm/*.ogg`、`assets/sfx/*.ogg`

全部声音都是 Python 程序现场合成的（numpy + scipy + soundfile），**不含任何采样素材**。
同样的代码与依赖版本，逐样本生成相同的 PCM（见第 8 节）。

---

## 1. 引擎怎么用到它们

| 事实 | 出处 | 对音频的含义 |
| --- | --- | --- |
| 按 `assets/<bgm\|sfx>/<id>` 依次找 `.ogg / .mp3 / .wav / .flac` | `src/engine/Engine.cpp` 的 `Impl::audioFor` / `resolve` | 文件名就是 id，扩展名 `.ogg` |
| BGM 流式解码、`MIX_PROP_PLAY_LOOPS_NUMBER = -1` 整文件循环 | `Engine::playBgm` | **一个文件就是一个完整的循环周期**，首尾必须无缝 |
| 音效预解码（`predecode = true`），`MIX_PlayAudio` 一次性播放 | `Engine::playSfx` | 音效要短、起音干净 |
| SDL3_mixer 3.2.4 内置 stb_vorbis | `build-octo/SDL3_mixer.dll` | 不需要额外的 libvorbis DLL |
| 引擎**没有音量接口** | `Engine.h` | BGM 与音效按文件本身的电平直接相加，所以响度在这里统一定死（第 5 节） |
| 地图 BGM 写在 `.tmj` 的 `bgm` 属性里（13 个 id） | `maps/*.tmj`（由 `tools/mapgen/` 生成） | 本工具登记表 `catalog.MAP_BGM` 钉着这 13 个 id，少一个就报错 |

施工图 1.2 节写的是 `assets/bgm/*.wav`；实际交付 `.ogg`：引擎本来就先找 `.ogg`，而十八首 BGM
若存 WAV 约 270 MB，OGG（Vorbis 质量 0.42）合计约 22 MB。

## 2. 重新生成

```bash
python tools/audiogen/audiogen.py                      # 全部生成到 assets/，结束时自动自检
python tools/audiogen/audiogen.py --only bgm_town,break # 只生成这几条
python tools/audiogen/audiogen.py --list                # 列出全部 id、时长、用途
python tools/audiogen/audiogen.py --out D:/tmp/audio    # 生成到别处（下面照样分 bgm/ sfx/）
python tools/audiogen/audiogen.py --verify              # 不生成，只检查 assets/ 里已有的文件
python tools/audiogen/audiogen.py --verify --plots D:/tmp/plots   # 顺带画波形 / 短时响度 / 声谱图
python tools/audiogen/audiogen.py --determinism         # 两个独立进程池各渲染一遍，逐样本比对 PCM
python tools/audiogen/audiogen.py --report --only bgm_inn         # 打印这首曲子每条声部的配平记录
```

- 依赖：Python ≥ 3.10（实测 3.14）、numpy、scipy、soundfile（libsndfile ≥ 1.1，带 Vorbis 编码）；
  matplotlib 只在 `--plots` 时用。
- 耗时：14 个进程并行，全部 48 条约 40 秒；单首 BGM 渲染 12–31 秒（真峰值限幅要做 4 倍过采样，占了一半）。`--jobs N` 调进程数。
- 退出码：自检有任何一项 FAIL、或确定性比对不一致，返回 1。
- 坑：libsndfile 1.2.2 的 Vorbis 编码器一次 `sf.write` 几十秒数据会**直接崩掉进程**（无异常可捕获，
  进程池里表现为 `BrokenProcessPool`）。`encode.py` 按 8192 帧分块写，结果等价。

## 5. 响度与格式

- 44.1 kHz，全部立体声（音效也是：`verify` 对每个文件都查声道数）。音效「做宽」用一对系数反号的
  Schroeder 全通，幅频严格为 1——左右能量、音色都与原声相同，折成单声道最多损失 2 dB。
- **BGM**：积分响度 **-16 LUFS**（ITU-R BS.1770-4，K 加权 + 门限，按循环周期计），真峰值 ≤ -1 dBTP。
  K 加权系数按 libebur128 的写法在 44.1 kHz 上重算；同一公式在 48 kHz 上与标准公布的系数一致到 1e-15
  （`dsp._k_weight_selftest()`）。
- **音效**：按角色分档的最大瞬时响度（上表），真峰值 ≤ -1 dBTP。分档思路：界面音最轻（光标 -27，一局要响几千次，
  不能盖过 BGM）；打击 -15 左右；破势 -11 是全作最响的一声；短曲与 BGM 同量级。
- 峰值以**解码回来的结果**为准：`encode.py` 编一遍、解一遍、量样本峰值与真峰值，超了就整体压低再编（最多三轮）。
- 音效开头垫 8 ms 静音：Vorbis 的 MDCT 会把起音往前「抹」一点，起音若落在流的第 0 个样本上，
  解码出来的第一个样本就不是 0（触发时一个小台阶）。垫了之后解码从 0 起，8 ms 的延迟觉察不到。
- 编码：OGG Vorbis，BGM 质量 0.42、音效 0.5。十八首 BGM 合计 22.41 MB，三十条音效 1.01 MB。

## 6. 音乐上的做法（为什么听起来是修仙古风）

- **五声音阶**：宫商角徵羽，每首换调式（见曲目表）。偏音只在三处当色彩：墨府的清角/变宫（不安）、
  首领战低音的 ♭E（压迫）、识海的 ♭7/#4（诡谲）。没有导音、没有属七到主的西洋式终止。
- **和声**：空五度、四度垫底；副旋律多用「支声」——把主旋律在五声音阶上平移两级（`score.penta_shift`），
  得到民乐合奏里常见的平行三、四度。
- **旋律**：简谱写成（`score.parse`，逐小节核对拍数）；乐句按起承转合，常用「同头换尾」与「鱼咬尾」。
- **乐器**（全部合成，`plucked.py` / `sustained.py` / `percussion.py`）：
  - 古筝、琵琶、古琴、大阮、扬琴：Karplus-Strong 拨弦（每个音高算一次弦的冲激响应，按音符卷激励；
    分数延迟用全通；按音、揉弦、滑音靠变速重读；摇指/轮指是同一根弦上的一串激励）。
  - 笛子、箫：谐波加法合成 + 气声噪音 + 延迟起振的颤音；笛子另有笛膜嗡鸣。
  - 二胡、中胡、大胡：带限锯齿（polyBLEP）+ 琴筒共鸣峰 + 弓噪，揉弦深、滑音多；低于二胡空弦（D4）的副旋律交给中胡。
    笙：簧片音色，和弦各音微失谐。
  - 打击乐：模态合成。小锣敲下去音高上翘、大锣下沉（京剧锣鼓的特点），鼓皮受力音高先高后落，
    编钟「一钟双音」并带青铜钟的慢拍频。
- **音域**：主旋律按真乐器音域写；低音、固定音型、和声垫超出音域的音用 `score.fold` 按八度折回
  （真乐手够不着的音就是这么处理的）。另有一道体检：十五首纯五声的曲子里没有一个五声以外的音、
  声部之间没有持续的小二度与三全音；这三样只出现在墨府、首领、识海三首里，且都是有意写的。
- **人性化**：每个音的起拍 ±几毫秒、力度 ±百分之几（固定种子），叠乐句弧线与强弱拍。
- **空间**：卷积混响，IR 程序生成（分频段指数衰减噪声 + 早期反射 + 可选离散回声），八种房间（`dsp.ROOMS`）。
- **配平**：每条声部写相对响度（主旋律 0、伴奏 -8 之类），渲染后按 BS.1770 实测再补增益——
  平衡是量出来的，不靠猜合成器的电平。`--report` 可以看每首的配平记录。

## 7. 无缝循环怎么保证

一首曲子在内存里就是长度为 L 的一个周期，**每一道工序都按周期信号来做**：

1. 音符越过曲尾的余音绕回曲首（`dsp.mix_into(circular=True)`）；起拍被人性化挪到 0 之前的音绕到曲尾。
2. IIR 滤波先用曲尾热身再滤（稳态响应）；混响、回声做线性卷积后把伸出 L 的尾巴折回开头。
3. 环境声（流水、风、低语）用逆 FFT 合成，天然以 L 为周期；零星事件（水滴、鸟叫）按模 L 摆放。
4. 限幅器的释放按周期信号算（块序列接两遍取后一遍）；响度按循环周期测。
5. 人性化偏差按「第几个音」抽取，不按时间抽取——每一遍循环里同一个音的偏差都一样。

所以接缝处与曲中任何一处没有区别。自检另外从解码结果上查三件事（`verify.py`）：
跨接缝的样本**台阶**、**折角**（二阶差分）各不大于两侧 20 ms 内最大值的 1.5 倍，跨接缝**掉电平**不超过全曲
相邻 50 ms 掉幅的 99 百分位（下限 3 dB；曲首的强拍是「涨」，不算）。

这三道检查自己也验过：把十八首故意弄坏再查——抹掉开头绕回来的混响尾巴，18/18 被抓出；在任意位置切开重接，
13/18 被抓出（漏掉的 5 首切口恰好落在密集织体里，前后样本本来就跳得一样大）；没弄坏的原文件 0 误报。

## 8. 确定性

- 所有随机数来自 `np.random.default_rng(seed)`，种子是 id 与声部名的 CRC32（`score.seed_of`），
  不用 Python 内置 `hash()`（它逐进程随机化）。缓存（弦冲激响应、打击乐变体）是纯函数、只读数组。
- `--determinism`：两个独立的进程池各渲染一遍，比最终 PCM（float32）的 sha256。
- **OGG 文件字节不是确定的**：Ogg 容器里有随机的流序列号。不做字节级门禁；确定的是 PCM。
- 换 numpy / scipy 版本或换 CPU，浮点结果可能有末位差异（FFT 实现不同），那不算漂移。

## 9. 加一首新曲

1. 在 `tools/audiogen/songs_world.py`（野外市井）/ `songs_sect.py`（宗门室内）/ `songs_special.py`（点播）里写一个函数，
   返回 `mixer.Song(...)`：旋律写成简谱常量，伴奏用 `arpeggio / bassline / chords / hits` 按和声根音表生成，
   每条声部给一个相对响度 `level`。同一件乐器若在不同段落里一会儿主奏、一会儿垫底，拆成两条声部各自配平
   （配平量的是整条声部的平均响度，合在一起会让轻的那段整段沉下去）。
2. 在该模块末尾的 `SONGS` 字典里登记 id。
3. `python tools/audiogen/audiogen.py --only <id>` 生成并自检；`--verify --only <id> --plots <目录>` 看图。
4. 要挂到地图上：改 `tools/mapgen/` 里那张图的 `bgm` 属性再重跑生成器（不要手改 `.tmj`），
   并把 id 加进 `catalog.MAP_BGM`。

简谱小语言速查（完整说明见 `score.py` 文件头）：

| 记号 | 意思 | 记号 | 意思 |
| --- | --- | --- | --- |
| `1`–`7`、`0` | 音级、休止 | `#` / `b` 前缀 | 升 / 降半音 |
| `'` / `,` 后缀 | 高 / 低八度 | `_` / `.` / `-` 后缀 | 减半 / 附点 / 加一拍 |
| 独立的 `-` | 延长前一个音一拍 | `\|` | 小节线（逐小节核对拍数） |
| `(6)5` | 倚音 | `/5` | 上滑音（从下方邻音滑入） |
| `~` `*` `>` `!` | 揉弦、摇指/轮指、重音、顿音 | `^` `v` `s` `o` | 打音、下滑音、从前音滑来、泛音 |
| `;` | 换气断句 | `@p` `@mf` `@0.6` | 力度 |

## 10. 加一个新音效

1. 在 `sfx_ui.py` / `sfx_battle.py` / `sfx_jingle.py` 里写 `render(rng) -> ndarray`（单声道或 `(2, n)`），
   用 `sfx_common` 的积木（`pluck`、`place`、`noise_sweep`、`reverb`、`render_ensemble`……）。
2. 在模块末尾的 `SFX` 元组里登记 `Sfx(id, 用途, 做法, render, 目标响度, 最短秒数, 最长秒数)`。
3. 生成、自检。收尾（去直流、剪尾、响度归一、真峰值限幅、开头 8 ms 静音）由 `finalize_sfx` 统一做。
4. 使用：Lua 脚本 `sfx("<id>")`；C++ `engine.playSfx("<id>")`。

## 11. 自检输出怎么读

`--verify` 逐文件解码后打一张表：时长、声道、峰值（样本）、真峰（4 倍过采样）、响度（BGM 为积分、音效为最大瞬时）、
RMS、直流、NaN、接缝（BGM：台阶/折角倍数、掉电平/门槛）或首尾（音效：首样本、尾 10 ms 电平、峰值时刻）、结论。
`--plots` 每个文件一行：波形、3 秒窗短时响度（红线 -16）、对数频率声谱图。

交付时另做过两道「用游戏自己的东西」的检查（脚本不在仓库里，做法记在这里，需要时照做）：

- **进图加载**：`build-octo/fanren.exe --assets . --map <图> --screenshot <png>`（`SDL_VIDEODRIVER=dummy`），
  十三张挂 BGM 的图各跑一次，stderr 里没有「找不到音频资源」「载入音频…失败」。对照组：把 `bgm_village.ogg`
  临时挪走再跑，stderr 出现 `WARNING: 找不到音频资源 bgm/bgm_village`——证明日志抓得到、音频子系统确实起来了。
- **游戏的解码器**：用 ctypes 直接调 `build-octo` 里的 SDL3_mixer（内置 stb_vorbis），内存混音器、
  `loops = -1` 按引擎的方式播过循环点：48 个文件全部能解，帧数与 libsndfile 逐帧相同，
  BGM 越过循环点的输出与「解码结果首尾相接」相差 ~1e-7（float32 舍入量级）——循环点没有空隙、没有错位。

## 12. 已知限制

- 纯合成的乐器是「像」而不是「是」：古筝、琵琶的拨弦最像；笛子、二胡是加法/减法合成，
  胜在音高表现（滑音、揉弦）而非音色逼真。
- 引擎侧（不归本路改）：`playBgm` 每次进图都从头播放，同一首 BGM 在两张图之间切换也会重头来；没有淡入淡出；
  没有音量接口（BGM 与音效的相对响度只能靠第 5 节的约定）。
- 自检用 libsndfile（libvorbis）解码，游戏用 stb_vorbis 解码，两者对同一文件的输出有极小的数值差异。
