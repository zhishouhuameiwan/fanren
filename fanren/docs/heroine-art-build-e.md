## 2. 对白里的立绘：摆位的数

屏幕上 420×630（表里每格 840×1260），右边距 60：`x = 1280 − 60 − 420 = 800`。

| 情形 | 立绘矩形 | 画到哪一行 |
| --- | --- | --- |
| 框在底部（常态，框 `48,472,1184×200`） | `800, −118, 420×630`：底边 512 = 框顶 472 + 40 | 只画到框顶金线下 3（`kBustTuck`），即屏幕 y = 475 |
| 框因选项长高（框顶 < 472） | 同上：底边不跟着抬，最高到「没有选项时的框顶 + 40」 | 画到这一帧框顶下 3 |
| 框被挪到顶边（`keepHeroInSight` 抬到 48） | `800, 90, 420×630`：底边贴屏幕底 | 整幅 |
| 框只被抬到半中腰 | 头顶落在框底以下 12：`y = 框底 + 12 − 188`，下半截出屏 | 整幅 |

- **头顶线**：格子里头顶在第 376 行（屏幕 188，`kBustHeadLine`；`busts.py` 的 `HEAD_LINE` 是它的两倍）。框在底部时头顶约在屏幕 y = 70，
  框贴顶时约在 y = 278（在框底 248 之下）。人物从头顶到格底是 1260 − 376 = 884 格像素，屏幕上约 442 高。
- 淡入淡出：`kBustFadeSeconds = 0.15`；对白收起（栈里没有对话框）超过 `kBustLingerSeconds = 0.25` 秒清台。
  换句时引擎本来就空一帧（旧框在 update 里收起，新的一句下一帧才由脚本压上来），这一帧不清台、立绘跟框一起缺一帧。
- 说话人不在对话框的 `onEnter` 里交给立绘台：路径行动一次压好几层对话框（后进先出），`onEnter` 全在同一帧、次序与上屏相反。
  改成每帧改栈之后由 Application 认最上面那一层，换了才交；叠着的几层里也只有那一层画立绘。
- 画在框之下：名签、两块键位牌、「自动」小标、跳过确认框都在后面画，压在立绘上面。左上角的地名与目标框在 x < 560，立绘从 800 起，不碰。

## 4. 打包工具 `tools/artgen/busts.py`

```
python tools/artgen/busts.py [--src <原图目录>]           # 写 assets/art/busts/*.png 与 data/visual/busts.json
python tools/artgen/busts.py [--src <原图目录>] --check   # BUSTS_IN_SYNC / BUSTS_IN_SYNC_PARTIAL / BUSTS_OUT_OF_SYNC
```

- 原图目录缺省：环境变量 `FANREN_BUST_SRC`，再没有就是仓库里的 `docs/heroine-art/final/`（不入库；主检出里路 P 就出到那里）。
- 一张原图：按 alpha > 16 找外框裁边 → 等比缩放使「头顶→外框底」落在「头顶线→格底」（比格子宽就改按宽缩，打一行注意）→
  水平居中 → 在预乘透明度上 LANCZOS 缩（不出黑边）。清单里每个角色可给 `head_adjust`、`x_adjust`。
- 确定性：同样输入两次输出逐字节相同（`--check` 从原图重打一遍逐字节比，已跑过：`BUSTS_IN_SYNC`）。PNG 固定压缩级别，JSON 键排序、LF。
- `busts.json` 的 `files` 记每张图的 sha256，`--check` 核；`assets/art/busts/` 下多出没登记的图也报。

## 7. 没做成的、拿不准的、施工图里不合理的地方

1. **420×630、底边在框顶下 40，格子顶在屏幕 y = −118。** 人物若铺满格子，头必出屏。我在格子里留了头顶线（376 格像素 = 屏幕 188），
   人物实际只有约 442 高，不是方案第 5 节写的「560–620」。要人更大，只能让框压住更多身子（底边更低），那就和「底边在框顶下 40」冲突——请主会话定。
2. **框是半透明的。** 立绘真画到框后面，那 40 像素会隐约透出来、压在字底下。我改成只画到框顶金线下 3 像素（切口叫金线压住），看上去仍是「从框后面探出来」。
3. **框只被抬到半中腰时（施工图没写这一种）**，照「贴屏幕底」脸正好在半透明的框后面（改前的样子我拍过，脸隔着框看得见）。改成头顶落在框底以下 12，下半截出屏。
   框贴到顶边时与施工图一致。
4. **选项多、框长高时**立绘不跟着往上抬（不然三个选项就把头顶推出屏幕），多出来那截由框压住。
5. **主角站在屏幕最右边时（镜头贴着地图右沿）立绘会挡住他和说话的 NPC**（例：百药园茅屋里）。左边是地名与目标框，不能挪；没处理，记在这里。
6. 伙伴插话气泡在说话人不在画面上时会退回成一句普通对白：我让它**也不带立绘**（照「插话不出大图」），小头像照旧。
7. 表里只放**画了的**表情格（试跑只有 1 格、`cols = 1`），没画的指回 normal；不是每张都固定四格。施工图两处说法（「一行四格」与「没画就指回 normal」）我取了后者。
8. **清单入库**（`tools/artgen/busts_manifest.json`），原图不入库。施工图说「输入是 final/ 下的原图与一份清单」，清单放仓库里 `--check` 才知道该有哪些图。
9. 第 8 章脚本里陈巧倩的角色 id 是 `chen_qiaoqian`（不是 `chen_shimei`），表里没登记，第 8 章她说话没有立绘。路 P 出图后在清单的 `roles` 里加上就行（要按章分时再加 `min_chapter`）。
10. 方案第 5 节的「说话的亮、不说话的压暗」没做：同一时刻只有一个人的立绘（两人前后说话时交叉淡化）。
11. 每张满表 3360×1260，显存约 17 MB；纹理按路径缓存、不释放。七套全进来约 120 MB。眼下够用，以后若要省可以在离开对白时卸。
12. 试玩检查点 `build-e/bust-demo.sav`（不入库）：由 `saves/ch07-jindi.sav` 改出（置 `ch07.chujindi`、`ch07.nangong`，人放在百药园历练设施前），
    只为让人一打开就能见到她开口。第 7 章里她用自己的名义开口的地方只有历练「禁地旧境」那一段与禁地荒山的「打探」，主线里没有。
13. 禁地荒山那条「打探」（`chen_dating`）的话是一段动作描写（「她什么也没说，把脸转了过去」），却以她的名义说出——
    现在会配上她含笑的立绘，画文不搭。路 P 的 `angry`（冷）格到了以后，这条可以让路径行动带表情；要不要改是内容上的事，没动。

各人原图的取景不同（头顶到膝的比例、发饰高低不一），统一头顶线后下巴高低差了约 40 格像素。用 `head_adjust` 把下巴对到格子第 395 行左右：
